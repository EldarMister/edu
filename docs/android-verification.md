## Android и уведомления

Firebase для EDU POS подключён. Проверка выполнена нативной сборкой на
Android-эмуляторе с Google Play services. Тестовые сообщения прошли через
настоящие Expo Push Service и FCM; аккаунты и данные относятся к QA-фикстуре.

| Сценарий | Результат |
| --- | --- |
| Foreground: один event через Socket.IO и remote push | После нормализации SDK 52 `dataString` появляется одна запись истории уведомлений |
| Приложение в фоне | ОС показывает remote уведомление |
| Процесс закрыт через Android `stop-app` | Перед отправкой PID отсутствует; ОС получает уведомление |
| Нажатие при закрытом процессе, WAITER | Приложение запускается и открывает заказ 101 официанта |
| Android Back после холодного перехода WAITER | Возврат в «Активные заказы» с заказом 101 |
| Нажатие при закрытом процессе, OWNER | Приложение запускается и открывает заказ 101 в Admin |

`stop-app` в этой проверке не означает Android `force-stop`. Проверка подтверждает
доставку и переходы на этом эмуляторе; непрерывная рация и озвучка после завершения
процесса не проверены. Подробности настройки: [mobile-notifications.md](mobile-notifications.md).

## Бизнес-сценарии и локальные проверки

Native UI QA работает только с синтетической loopback-фикстурой на порту `3009`.
Фикстура не подключена к production-базе. Её переходы подачи и частичной готовности
сверены с backend; отдельный HTTP smoke подтвердил полную/частичную подачу и
последующий переход к оплате.

Основные native маршруты реализованы; UI smoke покрывает официанта, владельца,
администратора, кухню, бар, гостевое QR-меню, очередь и платформу. Это не полная
проверка каждого поля формы, всех разрешений и всех размеров экранов.

Последний прогон: mobile typecheck и 60 тестов прошли, включая отмену PTT (6),
гонки оплаты при изменении заказа (9) и изоляцию TTS-сессий (13). Backend build
и 10 backend тестов прошли; Expo Android export также проверен. Эти проверки
дополняют UI QA, но не подтверждают внешние операции.

**Успешная оплата и чек — PASS на QA-фикстуре:** официант подал готовый заказ 102,
перешёл к оплате и принял смешанную оплату: наличные 300 + QR 120. `POST /payments`
вернул 200; оплаченный заказ исчез из активных. Экран «Оплата принята» остался
открытым, показал лимонад ×2, чизкейк ×1 и итог 420.

**Заявка печати — PASS на QA-фикстуре:** «Печать чека» отправила
`POST /receipt-prints` (200); глобальная панель показала ожидание администратора,
заказ 102, позиции и сумму 420. ADMIN загрузил список заявок и подтвердил предчек
102 (`POST approve` 200, загрузка чека 200). Android system print показал одну
страницу с правильной кириллицей, итогом 420 и пометкой «нефискальный счёт»;
диалог закрыт кнопкой Back без физической печати.

**Отмена и повторная печать — PASS:** после закрытия системного окна появляется
«Чек распечатан?». «Пока нет» и аппаратная Back оставляют заявку `approved`,
разблокируют действия; повторная печать снова открывает системное окно.
При отмене `POST /receipt-prints/:id/printed` не отправлялся. Исправление ждёт
возврата Android в приложение, поскольку Expo SDK 52 завершает `printAsync`
при открытии окна. Добавлены 14 регрессий печати; общий итог — 74 mobile теста.

**BAR — PASS на QA-фикстуре:** вход, доска и статистика станции `bar`
(`GET /kitchen/statistics` 200). В стоп-листе показаны только напитки: чай,
лимонад и кофе. Переключение чая отправило `PATCH stop-list` (200) с последующим
обновлением списка.

Не проверялись физическая ККМ, принтер, звучание на реальном телефоне, GPS,
production-транзакции и iPhone. HTTPS App Links требуют проверки на release-подписи
и корректного `assetlinks.json` настоящего PWA-домена.

## Короткая заметка для PR

Android source проверен локальными тестами и native QA на синтетических данных.
Настоящая Expo/FCM доставка подтверждена для foreground, background и закрытого
процесса; холодные переходы открывают заказ у WAITER и OWNER, Back у WAITER
возвращает список заказов. Подтверждены смешанная оплата, экран чека, заявка
печати, системное превью предчека и BAR статистика/стоп-лист. Production health
соответствует `main` `4b24251`; новые backend исправления ещё не выпущены.
Изменения backend: [draft PR #2](https://github.com/EldarMister/edu/pull/2), база
`main`. Физическая печать и production бизнес-операции не проверялись.
