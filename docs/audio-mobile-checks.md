# Проверка звука на телефонах

Изменения относятся к `frontend` (браузер / установленная PWA). Клиент Expo в `mobile` не изменён.

## Что исправлено

- Озвучка официанта, администратора, кухни и табло, сигналы и рация используют постоянные аудиоэлементы. Они разблокируются непосредственно при касании/нажатии, до сетевого запроса.
- При запрете воспроизведения появляется «Включить звук». Повторное касание запускает ожидающий звук. Ожидание старта ограничено 10 секундами; зависший проигрыватель больше не блокирует очередь навсегда.
- При возврате на страницу приложение пробует восстановить прерванное воспроизведение.
- Запись рации включает автоматическую регулировку микрофона. Полученная запись нормализуется с ограничением усиления до 8 раз и запасом по пиковому уровню, затем локально преобразуется в PCM WAV. Воспроизведение идёт через мультимедийный проигрыватель, как у уведомлений. Формат передачи серверу не меняется.
- При доступности Audio Session API приложение переключает режим записи обратно в playback после освобождения микрофона. Микрофон освобождается также при отмене, ошибке записи, таймауте сервера и уходе со страницы.
- Формат записи выбирается из поддерживаемых браузером: MP4, затем WebM/Opus, затем стандартный формат браузера. Серверное перекодирование не добавлено; совместимость старых версий Safari с WebM нужно проверять отдельно.

Основание для повторного использования элементов: [политика autoplay WebKit](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/). Режимы аудиосессии: [спецификация W3C Audio Session](https://www.w3.org/TR/audio-session/).

## Автоматическая проверка

В каталоге `frontend`: `npm run test:audio`, затем `npm run build`.
Тесты моделируют ограничения autoplay, повторный запуск, освобождение ресурсов, нормализацию и ошибки записи. Они не измеряют громкость физического динамика и не эмулируют аудиомаршрутизацию iOS.

## Проверка на устройствах перед выпуском

На iPhone в Safari и установленной PWA, затем на Android:

1. Открыть приложение, коснуться экрана, проверить «Тест звука» в профиле. Создать событие с другого устройства: должен прозвучать сигнал и голос с номером стола.
2. Отправить несколько событий подряд: фразы должны завершаться и очередь должна продолжать работу.
3. Передать одинаковую фразу обычным и тихим голосом: Android → iPhone, iPhone → Android. Сравнить слышимость рации с сигналом уведомления.
4. После передачи по рации проверить сигнал и озвучку. Индикатор микрофона должен исчезнуть после отпускания кнопки.
5. Отпустить кнопку до выдачи разрешения на микрофон, отказать в разрешении, отключить сеть во время запуска. Запись не должна оставаться включённой; повторная попытка должна работать.
6. Свернуть/открыть приложение, заблокировать/разблокировать экран, принять и закончить звонок. После возврата проверить новый сигнал и озвучку, при необходимости нажать «Включить звук».

Фоновое системное push-уведомление — отдельный механизм, управляемый ОС. Эти изменения исправляют воспроизведение внутри приложения; его нельзя считать проверенным по одному лишь звуку push на заблокированном телефоне.
