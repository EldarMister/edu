# EDU POS Android

Нативный клиент React Native / Expo SDK 52. Основа — ветка `mobile`; экраны, API и правила работы сверены с PWA в `main` (`beb2110`, включая общий календарь). Итоговые QA- и подписанная production-сборки приложения — из `8493339`. Нативные UI-проверки ниже относятся к `7d7557e` и `8493339`: подтверждены размер кнопки профиля, переход из корзины к заказам одним нажатием и повтор регистрации после нативной ошибки; новая удалённая доставка push ещё не подтверждена. Серверные изменения push, фоновых событий печати и tenant QR из PR #2 объединены с `main` и опубликованы на Railway в commit `489f8d0`.

## Экраны и функции

| Область | Реализовано |
| --- | --- |
| Официант | Столы, меню, варианты/вес, корзина, активные и завершённые заказы, редактирование, замена, отмена и вызов администратора, частичная готовность, перенос/передача стола, оплата, предчек и чек, смены, профиль |
| Кухня / бар | Заказы по станциям, приём, готовность всей позиции или части количества, отказ и подтверждение отмены, стоп-лист, статистика с периодами, голосовые настройки |
| Администратор / владелец | Статистика, заказы/доставка, заявки печати, столы/QR, меню, склад, ингредиенты, закупки, техкарты, движения, персонал/права, смены/отчёты/CSV, журнал, сверка оплат, настройки кафе/ККМ/очереди/геолокации/доставки |
| Гость | QR-меню, общий заказ нескольких гостей, варианты/комментарии, геопроверка при необходимости, отправка и статус заказа, очередь с голосом |
| Платформа | Отдельный вход, кафе, создание/приостановка/продление, сотрудники, очистка/удаление с подтверждением, состояние сервера |

Интерфейс использует палитру и иконки PWA, Inter с настоящими начертаниями, анимированные панели и переходы, кыргызский словарь PWA. Имена кафе, блюд и введённые значения не переводятся. Системное уменьшение анимации учитывается в переходах. Доступность действий определяется правами пользователя и статусом заказа.

## Окружение и запуск

Создайте локальный `.env`:

```dotenv
EXPO_PUBLIC_API_URL=https://edu-production-2395.up.railway.app
EXPO_PUBLIC_WEB_URL=https://edu-pos.up.railway.app
```

`/api` добавляется клиентом. Для локального сервера на Android-эмуляторе используйте `10.0.2.2` или `adb reverse`; на телефоне — сетевой адрес компьютера. Изменение переменных требует новой сборки JavaScript.

```powershell
cd mobile
npm ci
npx expo prebuild --platform android --no-install
npx expo run:android
```

Expo Go не заменяет нативную сборку для проверки рации и фонового push. `android/` генерируется конфигурацией Expo и не хранится в Git.

## APK

```powershell
cd mobile
npx expo prebuild --platform android --no-install
npm run build:apk
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`. Локальная конфигурация Expo использует тестовую подпись; для выпуска используйте постоянный release-keystore или EAS:

Для повторной сборки и копирования APK в `mobile/releases/`
запустите `npm run build:apk` из `mobile` после prebuild. Существующую release-подпись
можно передать как `npm run build:apk -- --signing-file C:\secure\signing.json`.
Этот локальный файл содержит `applicationIdentifier`, `keystorePath`, `keystorePassword`,
`keyAlias`, `keyPassword`; хранить его и `.jks` в Git нельзя. Скрипт передаёт пароль
Gradle через окружение и всегда заново собирает JavaScript. Относительный `keystorePath`
разрешается от каталога файла подписи. Пароли не записываются в исходники и вывод.

Скрипт по умолчанию использует production-адреса Railway. Другой публичный HTTPS API
можно явно передать через переменные окружения; локальные `.env` при сборке скриптом
не читаются. HTTP, loopback и частные сетевые адреса разрешены только в тестовом режиме
`npm run build:apk -- --qa`, который использует тестовую подпись и отдельное имя
`edu-pos-0.2.1-qa.apk`. Флаг `--qa` несовместим с release-подписью. Обычная сборка
отключает cleartext в основном AndroidManifest и проверяет совпадение версии native
проекта с `app.json` и `package.json`.

```powershell
eas build -p android --profile preview
eas build -p android --profile production
```

При длинном пути Windows запускайте сборку из короткого пути `subst` и обновите старые `.cxx`/autolinking cache. Выберите свободную букву:

```powershell
subst Q: "C:\path\to\edu-pos"
cd Q:\mobile
npm run build:apk -- --signing-file C:\secure\signing.json
```

## Фоновые уведомления

Android push использует Expo Push Service и Firebase FCM. Нужны соответствующие `com.edupos.mobile` файл `google-services.json` и FCM v1 credentials в текущем EAS проекте. Приложение сообщает об успешной подписке только после регистрации на сервере. Фоновые сообщения не зависят от открытого экрана или активной рации.

Firebase EDU POS подключён. На версии **0.2.0, 11 октября 2026** в Android-эмуляторе Google Play проверены настоящие Expo/FCM уведомления в foreground, фоне и после закрытия процесса через `stop-app`. Совместная доставка с Socket.IO создавала одну запись истории; холодное нажатие открывало заказ у WAITER и OWNER. Android Back у WAITER возвращал «Активные заказы». Android force-stop отключает push до следующего открытия приложения. В 0.2.1 реализованы повторное получение токена Expo SDK 52 после отказа или таймаута, обработка конкурентных запросов и безопасные диагностические коды; повторная доставка push этой версии пока не подтверждена.

Настройка описана в [mobile-notifications.md](../docs/mobile-notifications.md), результаты и пределы проверки — в [android-verification.md](../docs/android-verification.md).

HTTPS-ссылки меню/очереди/платформы и `edupos://` открывают нативные экраны. Автоматическая привязка HTTPS требует настоящего `assetlinks.json` на PWA-сервере с отпечатком release-сертификата. Включать её следует после настройки домена.

## Проверки и сервер

```powershell
cd mobile
npm run verify
npx expo export --platform android
cd ../backend
npm run build
node --test tests/*.test.cjs
```

Тесты проверяют обновление/смену аккаунтов, guest API, правила заказов, регистрацию push, дедупликацию, открытие уведомлений, конкурентные изменения настроек и привязку QR оплаты к кафе. Бизнес UI QA использует только синтетическую loopback-фикстуру `3009`; production-транзакции не выполнялись. На **0.2.0, 11 октября 2026** прошла нативная проверка подачи, смешанной оплаты 300 наличными + 120 QR и экрана «Оплата принята» с позициями чека. Эти результаты не подтверждают новый интерфейс 0.2.1. Физическая ККМ, принтер, звучание на телефоне и GPS не проверены.

Для **0.2.1**, исходников `8493339`, прошли mobile typecheck, **97 тестов** и **12 контрактов жизненного цикла заказа**. Итоговые QA- и production-сборки успешно собраны; все **127** встроенных исходников каждой совпали с текущими после нормализации CRLF/LF, а встроенные bundle совпали с результатами соответствующей сборки. Production APK `mobile/releases/edu-pos-0.2.1.apk`: **80 302 156 байт**, SHA-256 `ea1d4c280ef8d56892ba8effdf63fca76c2d6dd9bddc9aed53a2f3fe98aacc03`. Проверены существующий release-сертификат, v2-подпись, production-адреса, отсутствие QA-адреса и `usesCleartextTraffic=false`. Тестовый QA APK: **80 302 544 байта**, SHA-256 `06c89c6a397deb5e73259eca82df26bd8769d3bf6bf9c6938d9cf70ec2764259`; для распространения используется production APK.

На Android 18 октября подтверждены полная надпись кнопки включения уведомлений в одну строку, переход из полностью открытой корзины к заказам одним нажатием и четыре повтора нативной регистрации после ошибки. Google Play Services этого эмулятора возвращают `PHONE_REGISTRATION_ERROR`, а после одного ограниченного сброса — `SERVICE_NOT_AVAILABLE` и `AUTHENTICATION_FAILED`, также видимые у Google Messaging. Отказ происходит до Expo/backend, запросов `/push/devices` нет. Новая удалённая доставка push этой версии пока не подтверждена; её повторная проверка требует устройства с работающими Google Play Services.

Нативная QA исходников `7e149be` на отдельном профиле `EDU_UI_QA7` с Android 14 (API 34) шириной 360dp подтвердила вход WAITER, подачу заказа 102, переход к оплате, наличную оплату 420, центральную карточку успеха и последующий чек. Длинная протяжка ручки двигала панель и закрывала её; короткая — двигала и возвращала на место. Использовалась только синтетическая фикстура `3009`.

После этих снимков исправлены просвечивание тени через подсветку `Card`, сокращение «Смешанная», размеры и цвета футера оплаты и предупреждения об отсутствии QR. Изменения включены в успешно собранные QA- и production-APK из `7d7557e`. Нативная QA повторно подтвердила эти стили, наличную оплату 420, центральный успех и чек, протяжку и возврат корзины с видимой настоящей нижней навигацией. Повтор на `8493339` подтвердил переход из полностью открытой корзины к заказам одним нажатием.

У OWNER подтверждены боковое меню, его закрытие Android Back и открытие жестом, статистика, таблица персонала, история смен, фильтры/таблица заказов, протяжка и закрытие формы сотрудника без создания записи. Общий календарь привязан к полю, имеет семь колонок с понедельника и ограничения будущих дат; выбор 10 октября отображается как `10.10.2026`. В меню показаны поиск, действия, вкладки категорий и горизонтальная таблица блюд; в складе — сетка карточек и график; в настройках — группы полей кафе. Это не проверка каждой формы и всех размеров экранов. Сценарии, артефакты и ограничения: [mobile-ui-revision.md](../docs/mobile-ui-revision.md).

Исторический native smoke **0.2.0** покрывал основные пути официанта, OWNER, ADMIN, кухни, бара, гостевого меню/очереди и платформы, заявку печати, подтверждение предчека и его системное превью (одна страница, кириллица, 420), отмену и повторную печать, BAR статистику и изменение стоп-листа. Тогда также прошли backend build и 10 backend тестов; backend в этой доработке не менялся. Полный отчёт не заявляет проверку каждой формы и всех размеров экранов.

Production PWA доступна на `https://edu-pos.up.railway.app`, API — на `https://edu-production-2395.up.railway.app`. Серверные изменения из [PR #2](https://github.com/EldarMister/edu/pull/2) объединены с `main` и опубликованы: commit `489f8d0d21ad93e352fd5461c4958b9bd3a592c2`, Railway deployment `cf7100eb-880f-42bc-be6a-8595e3f21cf7`. Read-only health не заменяет проверку бизнес-операций на сервере.

Миграции в этой работе не выполнялись. Перед обновлением конкретного сервера проверьте его историю Prisma и примените необходимые миграции к выбранной базе. Включённая в ветку версия backend требуется для новых правил и API приложения.
